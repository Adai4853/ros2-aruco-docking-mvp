## 1. 这个项目在完成什么任务

**重要程度：★★★ 必懂**

机器人需要完成以下动作：

1. 从相机图像中找到指定的 ArUco 标记。
2. 判断标记位于画面左侧、中央还是右侧。
3. 估计机器人与标记之间的距离。
4. 先转向对准标记，再向标记前进。
5. 到达目标距离后停车。
6. 相机数据中断、标记丢失或前方出现障碍物时停车。
7. 把每个控制周期的数据写入 CSV，供实验统计和验收使用。

一句话概括：**相机和激光雷达提供环境信息，控制器计算速度，机器人执行速度，新的传感器数据再反馈给控制器。** 这叫作闭环控制。

### 1.1 完整数据流

```text
Gazebo 仿真世界
  ├─ 相机 ──> /camera/image_raw ───────┐
  ├─ 相机内参 -> /camera/camera_info ──┤
  └─ 激光雷达 -> /scan ────────────────┤
                                         ↓
                                  aruco_docking_node
                                         │
                         ArUco 检测、距离估计、安全判断
                                         │
                                         ↓
                                      /cmd_vel
                                         │
                                         ↓
                              TurtleBot3 转向、前进、停车
                                         │
                                         └─> CSV 实验记录
```

### 1.2 项目的 MVP 含义

**重要程度：★ 了解**

MVP 是 Minimum Viable Product，中文常译为“最小可行产品”。本项目的 MVP 标准是：核心自动停靠流程可以运行，主要安全条件可以触发，重复实验可以给出量化结果。

## 2. 电脑环境：Windows、WSL 2、Ubuntu 和 WSLg

### 2.1 Windows 与 Ubuntu 的关系

**重要程度：★★★ 必懂**

- Windows 是当前电脑的主操作系统。
- WSL 2 在 Windows 中运行一个 Linux 环境。
- Ubuntu 22.04 是 WSL 2 中使用的 Linux 发行版。
- ROS 2 Humble 和 Gazebo Classic 主要运行在 Ubuntu 中。
- WSLg 把 Ubuntu 中的 Gazebo 图形窗口显示到 Windows 桌面。

你看到的 Ubuntu 终端负责运行 Linux 命令；Gazebo 窗口负责显示仿真世界。

### 2.2 Windows 路径与 WSL 路径

**重要程度：★★★ 必懂**

同一个项目在两个系统中的路径写法不同：

```text
Windows: E:\Adai\Project\ros2-aruco-docking-mvp
WSL:     /mnt/e/Adai/Project/ros2-aruco-docking-mvp
```

`/mnt/e` 表示 WSL 挂载的 Windows E 盘。

### 2.3 终端、进程和 Ctrl+C

**重要程度：★★★ 必懂**

- 终端是输入命令和查看日志的窗口。
- 每个正在运行的程序都是一个进程。
- `Ctrl+C` 向前台进程发送中断信号，ROS 2 节点和 Gazebo会执行退出清理。
- Gazebo、停靠节点和实验工具可能分别占用不同终端。

关闭终端前先按 `Ctrl+C`，可以让节点发布零速度、关闭 CSV 文件并结束子进程。

### 2.4 环境变量

**重要程度：★★ 重要**

环境变量是当前进程及其子进程可以读取的配置值。本项目使用：

| 变量 | 用途 |
|---|---|
| `TURTLEBOT3_MODEL=waffle_pi` | 指定 TurtleBot3 型号 |
| `GAZEBO_MODEL_PATH` | 告诉 Gazebo 去哪里查找自定义模型 |
| `ROS_DISTRO=humble` | 表示当前 ROS 2 发行版 |

环境变量通常只对当前终端会话生效。新开终端后需要重新设置或通过脚本设置。

## 3. Linux 命令与 Bash 脚本

### 3.1 项目中常见命令

**重要程度：★★★ 必懂**

| 命令 | 含义 |
|---|---|
| `cd 路径` | 进入目录 |
| `source 文件` | 在当前终端加载环境配置 |
| `bash 脚本.sh` | 运行 Bash 脚本 |
| `python3 文件.py` | 运行 Python 程序 |
| `Ctrl+C` | 请求当前程序停止 |

### 3.2 `source` 为什么重要

**重要程度：★★★ 必懂**

运行 ROS 2 项目通常需要加载两层环境：

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
```

- 第一行加载 ROS 2 Humble 的系统环境，称为 underlay。
- 第二行加载当前项目编译后的环境，称为 overlay。

缺少第一层时，终端可能找不到 `ros2`。缺少第二层时，ROS 2 可能找不到 `aruco_docking` 包或读到旧版本。

### 3.3 Bash 严格模式

**重要程度：★★ 重要**

脚本顶部使用：

```bash
set -euo pipefail
```

含义如下：

- `-e`：命令失败时结束脚本。
- `-u`：读取未定义变量时报告错误。
- `-o pipefail`：管道中任一命令失败时让整条管道失败。

ROS 2 的 `setup.bash` 会读取一些允许为空的变量，所以项目脚本在加载环境前临时执行 `set +u`，加载完成后再执行 `set -u`。这就是此前 `AMENT_TRACE_SETUP_FILES: unbound variable` 的根本原因和处理方式。

### 3.4 进程清理与信号

**重要程度：★★ 重要**

脚本使用 `trap cleanup EXIT INT TERM` 注册清理函数。脚本退出、收到中断或终止信号时，清理函数会：

- 停止后台节点。
- 等待子进程结束。
- 发布一次零速度。
- 保留已经写入的实验文件。

这是机器人软件中的安全退出设计。

## 5. ROS 2 的核心概念

### 5.1 ROS 2 是什么

**重要程度：★★★ 必懂**

ROS 2 是机器人软件的通信与工具框架。它让相机、雷达、控制器和底盘驱动通过标准消息协作。

### 5.2 节点 Node

**重要程度：★★★ 必懂**

节点是一个具有明确职责的运行单元。本项目的核心节点名称是：

```text
/aruco_docking_node
```

它负责订阅传感器、运行识别与控制、发布速度、记录 CSV。

### 5.3 话题 Topic 与消息 Message

**重要程度：★★★ 必懂**

话题是一条持续传输消息的数据通道。发布者向话题发送消息，订阅者接收消息。

| 话题 | 消息类型 | 内容 | 节点用途 |
|---|---|---|---|
| `/camera/image_raw` | `sensor_msgs/Image` | 相机图像 | 检测 ArUco |
| `/camera/camera_info` | `sensor_msgs/CameraInfo` | 相机内参与畸变 | 计算距离 |
| `/scan` | `sensor_msgs/LaserScan` | 一圈激光距离 | 检测前方障碍 |
| `/cmd_vel` | `geometry_msgs/Twist` | 线速度与角速度 | 控制底盘 |

常用检查命令：

```bash
ros2 topic list
ros2 topic echo /cmd_vel
ros2 topic hz /camera/image_raw
```

### 5.4 发布与订阅

**重要程度：★★★ 必懂**

- Publisher：向话题发送消息。
- Subscription：接收话题消息并执行回调函数。
- Callback：消息到达时自动执行的函数。

本项目中的图像回调是 `_on_image`，雷达回调是 `_on_scan`，相机信息回调是 `_on_camera_info`。

### 5.5 服务 Service

**重要程度：★★ 重要**

服务是一问一答式通信。本项目通过 Gazebo 服务管理模型：

| 服务 | 用途 |
|---|---|
| `/spawn_entity` | 向仿真世界放入机器人、标记或障碍物 |
| `/delete_entity` | 从仿真世界删除指定模型 |

实验脚本先删除旧机器人，再在确定坐标重新生成机器人，保证每次实验起点一致。

### 5.6 参数 Parameter 与 YAML

**重要程度：★★★ 必懂**

参数把容易调整的数字和名称放到代码外部。本项目参数位于：

```text
src/aruco_docking/config/docking.yaml
```

修改 YAML 后需要重新构建并重新加载 `install/setup.bash`，节点才会读取安装目录中的新配置。

### 5.7 定时器与控制频率

**重要程度：★★ 重要**

节点以 `10 Hz` 运行控制循环，即理想情况下每秒计算并发布 10 次速度命令。周期为：

```text
1 / 10 Hz = 0.1 秒
```

图像回调负责更新观测，定时器负责按固定节奏控制机器人。这种结构把传感器到达时间与控制输出节奏分开。

### 5.8 Launch 启动文件

**重要程度：★★ 重要**

Launch 文件用于一次启动节点、设置参数和组合其他启动文件。

- `docking.launch.py`：启动自动停靠节点并加载 YAML。
- `simulation.launch.py`：组合 TurtleBot3 仿真和 ArUco 模型。
- `use_sim_time: true`：节点使用 Gazebo 仿真时间。

## 7. Gazebo 仿真

### 7.1 仿真的作用

**重要程度：★★★ 必懂**

Gazebo 在电脑中模拟地面、机器人、相机、雷达、标记、障碍物和物理运动。仿真可以重复设置相同条件，适合开发控制逻辑和自动实验。

### 7.2 World、Model、Link

**重要程度：★★ 重要**

| 概念 | 含义 | 示例 |
|---|---|---|
| World | 整个仿真世界 | 空世界和地面 |
| Model | 一个可放入世界的对象 | `waffle_pi`、`aruco_marker` |
| Link | 模型中的刚体组成部分 | 标记平面、障碍柱 |

### 7.3 SDF 模型文件

**重要程度：★★ 重要**

SDF 使用 XML 描述模型的尺寸、姿态、外观和碰撞体。

- `visual` 决定物体看起来是什么样。
- `collision` 决定物理碰撞形状。
- `static=true` 表示模型固定在世界中。
- `pose` 描述位置和旋转。

ArUco 模型包含白色底板和标记纹理。白色静区让黑色边框与背景形成稳定边界。障碍模型包含红色圆柱外观和圆柱碰撞体。

### 7.4 坐标与单位

**重要程度：★★★ 必懂**

Gazebo 常用米和弧度：

- `x`：前后方向。
- `y`：左右方向。
- `z`：高度。
- 旋转通常使用 roll、pitch、yaw。

实验起点为 `x=-1.50 m`，三组横向位置分别是 `y=0.00 m`、`0.35 m`、`-0.35 m`。

### 7.5 仿真时间

**重要程度：★★ 重要**

Gazebo 可以暂停、加速或减速，所以仿真时间与现实钟表时间可能不同。节点设置 `use_sim_time=true` 后，超时和 CSV 时间戳都跟随仿真时钟。

## 8. TurtleBot3 与差速运动

### 8.1 差速底盘

**重要程度：★★★ 必懂**

TurtleBot3 使用左右驱动轮。两轮速度关系决定运动：

| 左右轮状态 | 机器人动作 |
|---|---|
| 两轮同速向前 | 直行 |
| 左轮较慢、右轮较快 | 向左转 |
| 左轮较快、右轮较慢 | 向右转 |
| 两轮反向 | 原地旋转 |

ROS 2 底盘插件把 `/cmd_vel` 中的速度转换为轮速。

### 8.2 `Twist` 速度消息

**重要程度：★★★ 必懂**

本项目主要使用两个字段：

| 字段 | 单位 | 含义 |
|---|---|---|
| `linear.x` | m/s | 前进速度 |
| `angular.z` | rad/s | 绕竖直轴旋转速度 |

停车命令是：

```text
linear.x = 0
angular.z = 0
```

## 9. 相机、OpenCV 与 ArUco

### 9.1 图像数据

**重要程度：★★★ 必懂**

ROS 相机发布 `sensor_msgs/Image`。`cv_bridge` 把 ROS 图像转换为 OpenCV 的 BGR 图像数组。检测器随后把彩色图像转换为灰度图，减少 ArUco 检测需要处理的信息量。

### 9.2 ArUco 标记

**重要程度：★★★ 必懂**

ArUco 是由黑白方格组成的视觉标记。每个标记属于一个字典并拥有一个 ID。

本项目使用：

```text
字典：DICT_4X4_50
ID：0
实际边长：0.15 m
```

`4X4` 表示内部编码网格尺寸，`50` 表示该字典包含 50 个可用标记。

### 9.3 标记中心与水平误差

**重要程度：★★★ 必懂**

检测器得到标记四个角点，取四个角点横坐标的平均值作为标记中心：

```text
marker_center_x = 四个角点 x 坐标的平均值
```

归一化水平误差：

```text
horizontal_error = (marker_center_x - image_center_x) / image_center_x
```

- 误差接近 `0`：标记位于画面中央。
- 误差为正：标记位于画面右侧。
- 误差为负：标记位于画面左侧。

归一化以后，不同图像宽度可以使用相近的控制参数。

### 9.4 相机内参和畸变参数

**重要程度：★★ 重要**

`CameraInfo` 提供：

- 相机矩阵 `K`：焦距和主点位置。
- 畸变参数 `D`：描述镜头导致的图像变形。

像素坐标本身只能说明标记在图像中的位置。已知相机内参和标记实际尺寸后，程序才能估计三维距离。

### 9.5 PnP 距离估计

**重要程度：★★ 重要**

PnP 是 Perspective-n-Point。程序知道：

1. 标记四个角点在真实世界中的坐标。
2. 四个角点在图像中的像素坐标。
3. 相机内参与畸变参数。

OpenCV `solvePnP` 根据这些信息估计标记相对相机的旋转和平移。本项目使用 `SOLVEPNP_IPPE_SQUARE`，适合正方形平面目标。平移向量的 `z` 分量作为前向距离估计。

### 9.6 真实机器人中的相机标定

**重要程度：★★ 重要**

仿真相机参数由模型提供。真实相机需要完成标定，并确保 YAML 中的 `marker_size_m` 与打印标记的真实边长一致。尺寸误差会按比例影响距离估计。

## 10. 激光雷达与障碍检测

### 10.1 `LaserScan` 数据

**重要程度：★★★ 必懂**

激光雷达消息包含一组距离值。每个数组下标对应一个扫描角度：

```text
angle = angle_min + index × angle_increment
```

程序只选择机器人正前方扇区中的有效距离。

### 10.2 前方扇区和最近距离

**重要程度：★★★ 必懂**

项目配置：

```text
front_sector_degrees = 30°
obstacle_stop_distance_m = 0.28 m
```

程序取正前方 30° 扇区内的最小有效距离。当该距离小于或等于 `0.28 m` 时，控制器进入 `STOP / obstacle`。

选择最小值体现保守安全策略：扇区中最近的物体决定是否停车。

## 11. 状态机

### 11.1 状态机是什么

**重要程度：★★★ 必懂**

状态机把机器人行为划分为有限状态，每个状态有明确输出和切换条件。

```text
尚未看到目标 ──> SEARCH
看到目标 ──────> TRACK
到达/丢失/超时/障碍 ──> STOP
```

### 11.2 三个状态

| 状态 | 机器人行为 | 进入条件 |
|---|---|---|
| `SEARCH` | 原地低速旋转 | 启动后图像有效，尚未看到目标 |
| `TRACK` | 转向对准，并在允许时前进 | 检测到目标或短期记忆仍有效 |
| `STOP` | 发布零线速度和零角速度 | 到达、目标丢失、图像超时、障碍 |

### 11.3 停车原因

**重要程度：★★★ 必懂**

| `stop_reason` | 含义 |
|---|---|
| `reached` | 到达目标距离 |
| `target_lost` | 曾经看到目标，随后目标丢失超过容忍时间 |
| `image_timeout` | 相机图像停止更新或更新过慢 |
| `obstacle` | 雷达发现近距离障碍 |

停车原因写入日志和 CSV，便于区分正常完成与安全停车。

### 11.4 到达锁定

**重要程度：★★★ 必懂**

控制器到达目标距离后设置 `is_docked=True`。后续距离发生波动时，控制器仍保持 `STOP / reached`。这防止机器人在停车线附近反复启动和停止。

## 12. 比例控制与速度限幅

### 12.1 闭环控制

**重要程度：★★★ 必懂**

闭环控制持续执行：测量误差、计算动作、执行动作、重新测量。机器人接近目标时，距离误差逐渐减小，前进速度也逐渐减小。

### 12.2 角速度比例控制

```text
angular_z = clamp(-yaw_kp × horizontal_error)
```

**重要程度：★★★ 必懂**

- `yaw_kp` 决定转向纠偏强度。
- 负号把图像误差转换为正确转向方向。
- `clamp` 把角速度限制在安全范围内。

### 12.3 线速度比例控制

```text
distance_error = marker_distance - target_distance
linear_x = clamp(distance_kp × distance_error)
```

**重要程度：★★★ 必懂**

- 距离较远时，速度较大。
- 接近目标时，速度变小。
- 最大线速度为 `0.16 m/s`。

### 12.4 先对准再前进

**重要程度：★★★ 必懂**

当：

```text
abs(horizontal_error) > align_threshold
```

控制器把线速度设为零，只进行转向。水平误差进入阈值后才允许向前。这可以减少斜向接近和横向偏差。

### 12.5 速度饱和

**重要程度：★★ 重要**

比例计算可能产生很大的理论速度。`clamp` 函数把结果限制在：

```text
0 ≤ linear_x ≤ max_linear_speed
-max_angular_speed ≤ angular_z ≤ max_angular_speed
```

速度限幅保护仿真稳定性，也让参数行为更可预测。

## 13. 安全策略与优先级

### 13.1 安全判断顺序

**重要程度：★★★ 必懂**

控制器按以下顺序判断：

1. 图像是否超时。
2. 前方是否有近距离障碍。
3. 是否已经到达并锁定停车。
4. 当前是否有目标。
5. 是否需要停车或输出跟踪速度。

图像超时和障碍判断位于速度计算之前。传感器数据失效或路径受阻时，节点直接发布零速度。

### 13.2 检测记忆

**重要程度：★★★ 必懂**

图像检测可能偶尔漏掉一帧。`DetectionMemory` 保存最近一次有效检测 `0.75 s`：

- 新检测到来时更新记忆。
- 短暂漏检时继续使用最近观测。
- 记忆超过 `0.75 s` 后视为目标丢失。
- 仿真时间倒退时丢弃旧记忆。

检测记忆减少 `TRACK` 与 `STOP` 之间的频繁切换。图像整体超过 `1.0 s` 没有更新时，图像超时仍然优先触发。

### 13.3 退出时发布零速度

**重要程度：★★★ 必懂**

节点销毁时发布空的 `Twist`，其速度字段默认都是零。实验脚本清理时也额外发布一次零速度。这是防止底盘保留上一条运动指令的工程保护。

### 13.4 仿真安全与真实机器人安全

**重要程度：★★★ 必懂**

本项目的安全逻辑用于教学和 MVP 验证。真实机器人还需要急停按钮、速度分区、硬件故障处理、人员检测、制动距离测试和风险评估。

## 15. CSV 数据记录

### 15.1 为什么记录数据

**重要程度：★★★ 必懂**

肉眼观察只能说明机器人看起来是否运动。CSV 可以回答：何时看到目标、输出了多大速度、何时停车、停车原因是什么、距离误差有多大。

### 15.2 每一列的含义

| 列名 | 含义 |
|---|---|
| `timestamp_sec` | 仿真时间戳 |
| `state` | `SEARCH`、`TRACK` 或 `STOP` |
| `marker_found` | 当前图像是否检测到标记 |
| `marker_id` | 检测到的标记 ID |
| `horizontal_error` | 归一化水平误差 |
| `distance_m` | 相机估计距离 |
| `front_obstacle_m` | 雷达前方最近距离 |
| `linear_x` | 发布的前进速度 |
| `angular_z` | 发布的旋转速度 |
| `stop_reason` | 停车原因 |

### 15.3 追加写入与 `flush`

**重要程度：★★ 重要**

CSV 文件使用追加模式打开。每写一行就执行 `flush()`，让数据及时落盘。节点异常退出时，已经刷新过的数据仍可用于分析。

实验脚本为每次运行创建独立文件，并拒绝覆盖同名文件。这保证原始实验记录可以追溯。

## 16. 实验设计与统计

### 16.1 为什么需要重复实验

**重要程度：★★★ 必懂**

一次成功只能说明单次条件下完成任务。重复实验可以观察结果的一致性。

本项目包含：

| 起点 | 次数 |
|---|---:|
| 正前方 | 4 |
| 左偏 0.35 m | 3 |
| 右偏 0.35 m | 3 |
| 合计 | 10 |

### 16.2 控制变量

**重要程度：★★★ 必懂**

比较起点差异时保持以下条件一致：

- 标记尺寸与 ID。
- 相机参数。
- 目标距离。
- 控制参数。
- 仿真模型版本。
- 成功判定规则。

这叫控制变量。

### 16.3 指标

**重要程度：★★★ 必懂**

成功判定：运行记录中出现 `stop_reason=reached`。

```text
成功率 = 成功次数 / 总次数 × 100%
停车误差 = |实测停车距离 - 目标距离|
平均停车误差 = 所有有效误差的算术平均值
最大停车误差 = 所有有效误差中的最大值
目标丢失响应时间 = 首次 target_lost 时间 - 最后一次看到目标的时间
```

项目结果：

| 指标 | 结果 |
|---|---:|
| 成功次数 | 10 / 10 |
| 成功率 | 100.0% |
| 平均停车误差 | 0.0278 m |
| 最大停车误差 | 0.0298 m |
| 目标丢失停车时间 | 0.8 s |

### 16.4 精度、准确性与成功率

**重要程度：★★ 重要**

- 成功率回答“完成了多少次”。
- 平均误差回答“通常偏差多大”。
- 最大误差回答“最差一次偏差多大”。
- 重复实验的波动回答“结果是否稳定”。

工程验收通常需要多种指标共同描述系统表现。

## 18. Python 代码知识点

### 18.1 类与对象

**重要程度：★★ 重要**

项目把检测器、控制器、记忆器和记录器写成类。类定义数据和行为，对象是运行时创建的具体实例。

### 18.2 `dataclass`

**重要程度：★★ 重要**

`Detection`、`ControlCommand`、`MarkerObservation` 使用 `dataclass` 表达一组固定字段。`frozen=True` 让对象创建后保持只读，减少控制过程中被意外修改的风险。

### 18.3 `Enum`

**重要程度：★★ 重要**

`DockingState` 和 `StopReason` 使用枚举。枚举把允许值限制在明确集合中，避免字符串拼写差异破坏判断。

### 18.4 `Optional`

**重要程度：★★ 重要**

`Optional[Detection]` 表示变量可能有检测结果，也可能是 `None`。传感器软件必须明确处理“数据暂时不存在”的情况。

### 18.5 异常处理与失效安全

**重要程度：★★★ 必懂**

图像处理回调捕获异常、清空当前检测并记录错误。控制定时器继续运行，随后根据缺少有效数据进入安全停车。这里的设计目标是让感知故障转换为可解释的停车状态。

### 18.6 命名冲突

**重要程度：★★ 重要**

ROS 2 的 `Node` 内部使用 `_logger` 保存 ROS 日志器。项目最初把 CSV 记录器也命名为 `_logger`，覆盖了父类内部字段，导致：

```text
AttributeError: 'CsvLogger' object has no attribute 'info'
```

CSV 记录器改名为 `_csv_logger` 后，`get_logger().info()` 恢复正常。这个问题说明继承框架类时要注意父类内部属性名称。

## 19. 自动化脚本中的工程知识

### 19.1 等待服务准备

**重要程度：★★ 重要**

Gazebo 启动需要时间。启动脚本循环检查 `/spawn_entity`，最长等待 45 秒。服务准备后才生成模型。这叫 readiness check。

### 19.2 防止重复启动

**重要程度：★★ 重要**

启动脚本检测 `/spawn_entity` 是否已经存在。发现 Gazebo 正在运行时停止启动流程，避免两个仿真世界争用相同 ROS 资源。

### 19.3 实验超时

**重要程度：★★ 重要**

单次实验最长运行 90 秒。达到时间上限后以 `timeout` 结束。任何自动实验都需要终止条件，避免程序无限等待。

### 19.4 退出码

**重要程度：★★ 重要**

- `0` 表示成功。
- 非零值表示错误或实验失败。

自动化工具通过退出码判断下一步是否继续。

### 19.5 数据保护

**重要程度：★★★ 必懂**

实验脚本检查目标 CSV 是否已经存在。发现同名文件时要求使用新编号。这可以防止历史实验数据被覆盖。

## 20. 项目中出现过的典型故障

### 20.1 ROS 环境脚本报告未定义变量

**现象：** `AMENT_TRACE_SETUP_FILES: unbound variable`。

**原因：** Bash `set -u` 与 ROS 环境脚本中允许为空的变量发生冲突。

**处理：** `source` 前执行 `set +u`，加载完成后恢复 `set -u`。

### 20.2 节点启动后 `CsvLogger` 没有 `info`

**现象：** 节点启动时报 `AttributeError`。

**原因：** 子类字段 `_logger` 覆盖 ROS 2 `Node` 的内部日志字段。

**处理：** CSV 字段改为 `_csv_logger`。

### 20.3 Gazebo 能看到模型名称，画面中却难以识别标记

**原因：** 标记缺少白色静区、朝向错误、尺寸或材质路径错误。

**处理：** 添加 0.19 m 白色底板，把 0.15 m 标记平面旋转到正对相机，并校验材质路径。

### 20.4 节点在跟踪和停车之间快速切换

**原因：** 仿真图像偶尔漏帧，单帧检测结果短暂为空。

**处理：** 增加 0.75 s 检测记忆，并保留 1.0 s 图像超时作为独立安全条件。

### 20.5 自动实验提示 Gazebo 尚未准备好

**原因：** 基础场景进程已经停止，或当前 ROS 环境看不到 `/spawn_entity`。

**处理：** 保持 `start_docking_demo.sh` 所在终端运行，再在另一终端执行实验脚本。

### 20.6 Git 推送连接 GitHub 超时

**原因：** 浏览器与终端使用了不同网络通道，终端无法连接 `github.com:443`。

**处理：** 代理软件开启 TUN 模式后，终端 HTTPS 连接恢复，随后完成分支和标签推送。

## 26. 最应该记住的十句话

1. **ROS 2 节点通过话题交换消息。**
2. **相机负责找目标和估计距离，雷达负责检查前方障碍。**
3. **`/cmd_vel` 中的 `linear.x` 控制前进，`angular.z` 控制旋转。**
4. **状态机让搜索、跟踪和停车拥有明确规则。**
5. **比例控制让误差决定速度，限幅让速度保持在设定范围。**
6. **传感器数据超时、目标丢失和障碍物都会触发零速度。**
7. **YAML 保存可调参数，代码实现固定逻辑。**
8. **CSV 把运行过程变成可以统计和复查的证据。**
9. **测试验证小模块，闭环实验验证整个系统。**
10. **Git 保存版本历史，GitHub 保存远程副本并管理协作权限。**
