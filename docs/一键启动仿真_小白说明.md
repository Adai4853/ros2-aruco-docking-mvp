# ArUco 停靠仿真：一键启动说明

## 我们整理了什么

以前需要手动完成四件事：

1. 启动 Gazebo；
2. 等待 Gazebo 准备好；
3. 放入 ArUco 标记；
4. 放入 TurtleBot3 机器人。

现在这些动作已经收进 `scripts/start_docking_demo.sh`。脚本还会自动设置
`GAZEBO_MODEL_PATH`，让 Gazebo 能找到二维码图片和材质。

最直白地说：这个脚本就像“开实验室、等门打开、搬进二维码、搬进机器人”的值班员。

## 启动前

如果现在还有 Gazebo 在运行，请回到启动 Gazebo 的终端按一次 `Ctrl+C`。

`Ctrl+C` 的意思是：“请停止当前正在运行的程序”。它不会删除项目文件。

## 一条命令启动完整基础场景

在 Ubuntu 终端中输入：

```bash
cd /mnt/e/Adai/Project/ros2-aruco-docking-mvp
bash scripts/start_docking_demo.sh
```

正常情况下，Gazebo 左侧的 `Models` 下会出现：

- `ground_plane`：地面；
- `aruco_marker`：供摄像头识别的二维码停靠标记；
- `waffle_pi`：带摄像头和激光雷达的 TurtleBot3 机器人。

脚本只搭建试验场，不会启动自动停靠控制，所以机器人不会突然自己运动。

## 启动自动停靠

保持 Gazebo 运行，再打开一个 Ubuntu 终端：

```bash
cd /mnt/e/Adai/Project/ros2-aruco-docking-mvp
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch aruco_docking docking.launch.py
```

节点启动后会读取相机与激光雷达，识别二维码并向 `/cmd_vel` 发布速度。机器人会
接近二维码，并根据目标距离或安全条件停车。

## 看机器人的摄像头

让启动场景的终端保持运行，再打开一个新的 Ubuntu 终端，输入：

```bash
source /opt/ros/humble/setup.bash
cd /mnt/e/Adai/Project/ros2-aruco-docking-mvp
source install/setup.bash
rqt_image_view
```

在窗口左上角选择 `/camera/image_raw`。

这里可以把 ROS 2 想象成一个办公楼：

- `/camera/image_raw` 是摄像头不断投递照片的“传送带”；
- `rqt_image_view` 是站在传送带旁边看照片的显示器；
- `source .../setup.bash` 是把楼层通讯录交给当前终端，让它知道命令和程序在哪里。

`source` 只影响当前这个终端窗口，所以新开终端后通常需要再执行一次。

## 屏幕上的常见提示

下面这些提示目前可以忽略：

- `Unable to open audio device`：WSL 没给 Gazebo 提供默认声卡；本项目不用声音。
- `Missing model.config ... turtlebot3_autorace_2020`：Gazebo 的模型选择栏发现一个不完整的附带模型目录；不影响我们使用 `waffle_pi`。
- `Queue limit reached ... user_camera/pose`：Gazebo 界面相机消息来不及全部显示；一般不影响仿真物理和 ROS 2 话题。

真正需要关注的是包含 `process has died`、`spawn service failed` 或项目节点异常退出的错误。
