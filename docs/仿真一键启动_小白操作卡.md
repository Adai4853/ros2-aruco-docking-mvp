## 以后怎样启动

先把旧的 Gazebo 停掉：回到启动它的终端，按 `Ctrl+C`。

`Ctrl+C` 的意思是“请当前程序停止”，不会删除项目或文件。

然后打开一个新的 Ubuntu 终端，只运行：

```bash
cd /mnt/e/Adai/Project/ros2-aruco-docking-mvp
bash scripts/start_docking_demo.sh
```

脚本会自动完成四件事：

1. 启动 Gazebo 空世界；
2. 等待 Gazebo 的“放入模型入口”准备好；
3. 放入 ArUco 标记；
4. 放入 TurtleBot3 `waffle_pi`。

成功后，Gazebo 左侧 `Models` 应该出现：

```text
ground_plane
aruco_marker
waffle_pi
```

## 这些词到底是什么意思

- **Gazebo**：虚拟机器人试验场。机器人、地面、相机和物理运动都在里面模拟。
- **模型（model）**：仿真世界中的一个物体，例如机器人或 ArUco 标记。
- **SDF 文件**：模型的“施工图”，记录物体的大小、位置、外观、传感器等信息。
- **spawn_entity**：字面意思是“生成实体”，就是把一张模型施工图放进 Gazebo 世界。
- **source**：把某个软件的“地址簿”加载到当前终端，让终端知道 ROS 2 包和命令在哪里。
- **export**：给当前终端贴一张临时便签，例如告诉 Gazebo 去哪里寻找模型。关掉终端后通常失效。
- **话题（topic）**：ROS 2 节点之间持续传数据的频道。相机画面、速度命令和雷达数据都走不同频道。

例如：

- `/camera/image_raw`：相机不断发送的原始画面；
- `/camera/camera_info`：相机参数；
- `/scan`：激光雷达扫描结果；
- `/cmd_vel`：机器人接收前进和转向命令的频道。

## 查看机器人相机

保持 Gazebo 运行，再开一个新的 Ubuntu 终端：

```bash
cd /mnt/e/Adai/Project/ros2-aruco-docking-mvp
source /opt/ros/humble/setup.bash
source install/setup.bash
rqt_image_view
```

在窗口左上角选择：

```text
/camera/image_raw
```

这里显示的是**机器人摄像头看到的画面**，不是 Gazebo 主窗口中的上帝视角。以后 ArUco 识别程序读取的也是这条图像话题。

## 目前可以忽略的提示

- `ALSA`、`OpenAL`、`Audio will be disabled`：WSL 中没有给 Gazebo 提供音频设备。本项目不使用声音，可以忽略。
- `Missing model.config ... turtlebot3_autorace_2020`：Gazebo 左侧模型库发现了一个不完整的额外模型目录，不影响当前机器人和标记。
- `Queue limit reached ... user_camera/pose`：Gazebo 图形界面的相机位置消息短暂堆积，通常不影响仿真。
- 顶部关于 Gazebo Classic 生命周期的橙色提示：版本提醒，不是本次运行失败。

## 启动自动停靠

一键脚本负责搭建试验场。机器人刚出现时保持静止。保持 Gazebo 运行，再开一个
Ubuntu 终端执行：

```bash
cd /mnt/e/Adai/Project/ros2-aruco-docking-mvp
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch aruco_docking docking.launch.py
```

完整流程是：

```text
机器人相机画面
    → ArUco 识别节点找出标记位置
    → 控制器计算前进或转向速度
    → 向 /cmd_vel 发送速度
    → 机器人靠近并停在标记前
```

控制终端中的三种停车原因：

- `reached`：到达目标距离；
- `target_lost`：识别过标记后，标记消失；
- `obstacle`：激光雷达在前方检测到近距离障碍物。
